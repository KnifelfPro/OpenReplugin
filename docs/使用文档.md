# OpenReplugin 使用文档

当前发布坐标为 `io.github.knifelfpro`，版本 **3.3.0**。仓库：[Maven Central](https://central.sonatype.com)。

支持 **API 19–37**（Android 4.4 至 Android 17）。构建工具为 **Gradle 9.4.1 + Android Gradle Plugin 9.2.0**。宿主与插件应用代码可用 **Java 8 或 Java 17**（`replugin-host-lib` / `replugin-plugin-lib` 均以 Java 8 字节码发布）；构建本仓库自身需要 **JDK 17+**（Gradle 9 / AGP 9 的要求）。

完整示例见 [`sample`](../sample)。每种栈（Support / AndroidX / Kotlin / Compose / Fresco）都是一个独立 Gradle 工程，内含 `:host` 与 `:plugin` 两个 application，依赖均走 Maven Central。一行命令即可完成「插件编译 → 复制到宿主 assets → 宿主编译」：

```bash
cd sample/androidx && ./gradlew assembleSample
```

## 2. 接入宿主

### 2.1 settings.gradle

```gradle
pluginManagement {
    repositories {
        google()
        mavenCentral()
        gradlePluginPortal()
    }
}
dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
    repositories {
        google()
        mavenCentral()
    }
}

rootProject.name = "host"
include ':app'
```

刚发布后的几十分钟内，若 Central 尚未同步，可临时加上 `mavenLocal()`。

### 2.2 根 build.gradle

```gradle
plugins {
    id 'com.android.application' version '9.2.0' apply false
    id 'io.github.knifelfpro.replugin-host-gradle' version '3.3.0' apply false
}
```

### 2.3 app/build.gradle

```gradle
plugins {
    id 'com.android.application'
    id 'io.github.knifelfpro.replugin-host-gradle'
}

android {
    namespace 'com.example.host'
    compileSdk 37
    defaultConfig {
        applicationId "com.example.host"
        minSdkVersion 19
        targetSdkVersion 37
        multiDexEnabled true
    }
    compileOptions {
        sourceCompatibility JavaVersion.VERSION_17
        targetCompatibility JavaVersion.VERSION_17
    }
}

repluginHostConfig {
    useAppCompat = true
    useAndroidX = true
}

dependencies {
    implementation 'androidx.appcompat:appcompat:1.6.1'
    implementation 'io.github.knifelfpro:replugin-host-lib:3.3.0'
}
```

`replugin-host-gradle` 会在编译期往宿主 Manifest 写入插件坑位，并生成 `RePluginHostConfig`。

常用配置：

| 项 | 默认 | 说明 |
|---|---|---|
| `useAppCompat` | `false` | 插件 Activity 使用 AppCompat 主题时打开 |
| `useAndroidX` | `false` | 宿主已用 AndroidX 时打开 |
| `pluginDir` | `plugins` | 内置插件在 `assets` 下的目录 |
| `pluginFilePostfix` | `.jar` | 内置插件文件后缀（内容仍是 APK） |
| `countTask` | `2` | TaskAffinity 坑位组数 |

### 2.4 Application

推荐直接继承：

```java
public class HostApp extends RePluginApplication {
    @Override
    protected void attachBaseContext(Context base) {
        super.attachBaseContext(base);
        RePlugin.enableDebugger(base, BuildConfig.DEBUG);
        // 框架版本≥4：需与宿主 UI 同进程的插件必须加入白名单
        RePlugin.addMainPkg("pluginNameOrPackage");
    }

    @Override
    protected RePluginConfig createConfig() {
        RePluginConfig c = new RePluginConfig();
        c.setUseHostClassIfNotFound(true);
        c.setVerifySign(!BuildConfig.DEBUG);
        return c;
    }
}
```

框架版本 ≥ 4 时，未加入白名单的插件默认进程会映射到坑位。需要和宿主 UI 同进程的插件（WebView、Compose、共享静态状态）必须在 `attachBaseContext` 里调用 `RePlugin.addMainPkg("pluginNameOrPackage")`（别名和包名不一致时两边都加），且须在插件加载前调用。

已有 Application、不能改继承时：

```java
public class HostApp extends Application {
    @Override
    protected void attachBaseContext(Context base) {
        super.attachBaseContext(base);
        RePlugin.App.attachBaseContext(this);
    }

    @Override
    public void onCreate() {
        super.onCreate();
        RePlugin.App.onCreate();
    }
}
```

在 `AndroidManifest.xml` 里声明该 Application。

## 3. 接入插件

插件工程按普通 Android App 开发，再加插件 Gradle 插件和 `replugin-plugin-lib`。

### 3.1 settings.gradle

```gradle
pluginManagement {
    repositories {
        google()
        mavenCentral()
        gradlePluginPortal()
    }
}
dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
    repositories {
        google()
        mavenCentral()
    }
}

rootProject.name = "plugin-demo"
include ':app'
```

### 3.2 根 build.gradle

```gradle
plugins {
    id 'com.android.application' version '9.2.0' apply false
    id 'io.github.knifelfpro.replugin-plugin-gradle' version '3.3.0' apply false
}
```

### 3.3 app/build.gradle

`repluginPluginConfig` 必须写在 `android {}` 之后，插件要读 `applicationId` 等配置。

```gradle
plugins {
    id 'com.android.application'
    id 'io.github.knifelfpro.replugin-plugin-gradle'
}

android {
    namespace 'com.example.plugin.demo'
    compileSdk 37
    defaultConfig {
        applicationId "com.example.plugin.demo"
        minSdkVersion 19
        targetSdkVersion 37
        versionCode 1
        versionName "1.0"
    }
    compileOptions {
        sourceCompatibility JavaVersion.VERSION_17
        targetCompatibility JavaVersion.VERSION_17
    }
}

repluginPluginConfig {
    pluginName = "demo"
    hostApplicationId = "com.example.host"
    hostAppLauncherActivity = "com.example.host.MainActivity"
}

dependencies {
    implementation 'io.github.knifelfpro:replugin-plugin-lib:3.3.0'
    compileOnly 'androidx.appcompat:appcompat:1.6.1'
}
```

`replugin-plugin-gradle` 会在编译期把 Activity 等调用改到插件框架（例如改继承 `PluginActivity`）。业务代码仍可按普通 `Activity` 来写。

Compose 的 `ComponentActivity` 会改写成 `PluginComponentActivity`，`AppCompatActivity` 仍走 `PluginAppCompatXActivity`。

## 3.4 Jetpack Compose 插件

插件可以按普通 Compose 工程开发：`org.jetbrains.kotlin.plugin.compose` + Compose BOM，Activity 继承 `ComponentActivity` 或 `AppCompatActivity` 后 `setContent { ... }`。

```gradle
plugins {
    id 'com.android.application'
    id 'org.jetbrains.kotlin.android'
    id 'org.jetbrains.kotlin.plugin.compose'
    id 'io.github.knifelfpro.replugin-plugin-gradle'
}

android {
    compileSdk 37
    defaultConfig {
        minSdkVersion 23
        targetSdkVersion 37
    }
    compileOptions {
        sourceCompatibility JavaVersion.VERSION_17
        targetCompatibility JavaVersion.VERSION_17
    }
    buildFeatures { compose true }
}

dependencies {
    implementation 'io.github.knifelfpro:replugin-plugin-lib:3.3.0'
    implementation platform('androidx.compose:compose-bom:2026.08.00')
    implementation 'androidx.compose.ui:ui'
    implementation 'androidx.compose.material3:material3'
    implementation 'androidx.activity:activity-compose:1.13.0'
}
```

注意：

- 当前 Compose BOM 要求插件 `minSdk` ≥ 23。框架本身仍支持 API 19。
- Compose 运行时请打进插件 APK（或放到宿主并打开 `setUseHostClassIfNotFound(true)`，且版本必须一致）。
- 宿主需 `useAppCompat = true`、`useAndroidX = true`。
- 完整示例见 `sample/compose`。

`hostApplicationId` / `hostAppLauncherActivity` 供 `rpInstallPlugin`、`rpStartHostApp` 等调试 Task 使用。

## 4. 内置插件与外置插件

### 4.1 内置插件

1. 把插件工程打出的 APK **改名为 `{别名}.jar`**，例如 `demo.jar`。
2. 放到宿主的 `src/main/assets/plugins/`（sample 工程）或 `app/src/main/assets/plugins/`。
3. 宿主编译时会扫描该目录并生成 `plugins-builtin.json`。
4. 运行时可用文件名（不含后缀）或插件 `applicationId` 作为插件名。

```
host/src/main/assets/plugins/demo.jar   →  插件名 demo
```

### 4.2 外置插件

把 APK 下载或拷到本地后安装：

```java
PluginInfo info = RePlugin.install("/sdcard/demo.apk");
if (info != null) {
    RePlugin.startActivity(context, RePlugin.createIntent(info.getName(), "com.example.plugin.demo.MainActivity"));
}
```

正式环境请打开签名校验，并登记合法证书。传入的是签名证书字节的 MD5（大写十六进制），不是 SHA1；实现为 `CertUtils.md5(Signature.toByteArray())`：

```java
c.setVerifySign(true);
RePlugin.addCertSignature("你的证书MD5");
```

## 5. 常用 API

在**宿主**里：

```java
// 按包名或别名打开插件 Activity
RePlugin.startActivity(context,
        RePlugin.createIntent("com.example.plugin.demo", "com.example.plugin.demo.MainActivity"));
RePlugin.startActivity(context,
        RePlugin.createIntent("demo", "com.example.plugin.demo.MainActivity"));

RePlugin.startActivityForResult(activity, intent, requestCode, null);
boolean installed = RePlugin.isPluginInstalled("demo");
PluginInfo info = RePlugin.install(apkPath);
ClassLoader cl = RePlugin.fetchClassLoader("demo");
// 框架版本≥4：未加入白名单的插件默认进程会映射到坑位
RePlugin.addMainPkg("pluginNameOrPackage");
```

插件未安装时，可在 `RePluginCallbacks.onPluginNotExistsForActivity` 里走下载逻辑。

## 6. 本仓库本地开发

`sample/` 默认从 Maven Central 拉取 `io.github.knifelfpro:3.3.0`。调试尚未发布的框架改动时，先把 Library 发到本机，再在对应 sample 的 `settings.gradle` 里临时加上 `mavenLocal()`（可另用 `includeBuild` 指向 `replugin-host-gradle` / `replugin-plugin-gradle`）。

```bash
cd replugin-host-library && ./gradlew :replugin-host-lib:publish
cd ../replugin-plugin-library && ./gradlew :replugin-plugin-lib:publish
```

重新发布到 Maven Central：

```bash
cd replugin-host-gradle && ./gradlew publishAndReleaseToMavenCentral
cd ../replugin-plugin-gradle && ./gradlew publishAndReleaseToMavenCentral
cd ../replugin-host-library && ./gradlew :replugin-host-lib:publishAndReleaseToMavenCentral
cd ../replugin-plugin-library && ./gradlew :replugin-plugin-lib:publishAndReleaseToMavenCentral
```

凭据写在 `GRADLE_USER_HOME/gradle.properties`（本机若设置了 `GRADLE_USER_HOME`，不是 `~/.gradle`）。`publishAndReleaseToMavenCentral` 会上传并自动发布；若只用 `publishToMavenCentral`，需再到 [Central Portal Deployments](https://central.sonatype.com/publishing/deployments) 手动点 Publish。

## 8. 常见问题

**`plugins { id '...' }` 找不到插件**  
Plugin ID 必须是 `io.github.knifelfpro.replugin-host-gradle` / `io.github.knifelfpro.replugin-plugin-gradle`，并且 `pluginManagement.repositories` 里有 `mavenCentral()`。不要只用 `replugin-host-gradle`（那是本仓库 `includeBuild` 用的短 ID）。

**插件 Activity 主题崩溃**  
宿主打开 `useAppCompat = true`，用了 AndroidX 再打开 `useAndroidX = true`。

**外置插件安装失败**  
调试可 `setVerifySign(false)`。发布包必须校验签名，并保证插件与登记证书一致。

**Android 4.4 方法数超 64K**  
宿主打开 `multiDexEnabled true`，并依赖 `androidx.multidex:multidex`。`RePluginApplication` 会在 API &lt; 21 时安装 MultiDex。

**DEX file is not writable（Android 14）**  
框架加载插件 dex 前会把它设为只读，使用 3.3.0 即可。

**Java 8 / Java 17 都能用**  
`replugin-host-lib` 和 `replugin-plugin-lib` 都以 Java 8 字节码发布，宿主和插件的 `compileOptions` 可自由选 `JavaVersion.VERSION_1_8` 或 `JavaVersion.VERSION_17`，二者互不影响、可混用（比如宿主 17、插件 8）。选 17 时可直接用 switch 表达式、text block、pattern matching 等语言特性；若要用 `String.formatted()` 等 Java 9+ API，需自行打开 core library desugaring。
